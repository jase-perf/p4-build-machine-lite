# P4 Build Machine Lite

[English](README.md) · 日本語 · [简体中文](README.zh-CN.md)

余っているパソコンを、チームのビルドマシンにします。誰かが P4 にサブミットするとゲームをビルドし、チームがダウンロードできる Web ページに置きます。

Jenkins や TeamCity、Horde までは要らないけれど、ビルドは自動化したい。そんなインディーチーム、個人開発者、ゲームジャム向けです。中身は exe か Python ファイルが 1 つだけです。

## セットアップ

ゲームをビルドできるパソコンと、p4 コマンドライン (P4 CLI、perforce.com から入手) が必要です。

1. **ビルドスクリプトをプロジェクトに追加します**。サンプルフォルダの中身をすべて、プロジェクトの一番上のフォルダ (`project.godot`、`Assets`、`.uproject` があるフォルダ) にコピーして、サブミットしてください: [Godot](examples/godot) · [Unity](examples/unity) · [Unreal](examples/unreal)。`build.bat` (Windows) と `build.sh` (macOS、Linux) は両方とも残しておきましょう。どの OS のビルドマシンでもビルドできるようになります。
2. **ビルドマシンを入手します**。[Windows、macOS、Linux 用](../../releases/latest)をダウンロードして展開してください。Mac 用は Apple シリコン向けです。(Python 3.9 以降があれば、このリポジトリの `build_machine.py` を使うこともできます。)
3. ビルド用のパソコンで**起動します**。`build-machine` をダブルクリックするか (Linux では `./build-machine` を実行)、`py build_machine.py` (Windows) または `python3 build_machine.py` (macOS、Linux) を実行してください。署名していないので、初回は Windows に「Windows によって PC が保護されました」と表示されたり (「**詳細情報**」、「**実行**」の順にクリック)、macOS に開くのを拒否されたりすることがあります (システム設定 › プライバシーとセキュリティで「**このまま開く**」をクリック)。Windows に確認されたら、プライベートネットワークとパブリックネットワークの両方でファイアウォールの通過を許可してください。チームメイトがアクセスできるようになります。
4. 最初は ini ファイルを作ったところで止まります。**`build-machine.ini` を記入します**。このファイルは初回起動時に作られ、Windows と macOS では自動で開きます。`stream` を設定し、プロジェクトがストリームの一番上ではなくサブフォルダにある場合は `project_folder` も設定してください。p4 コマンドにサーバーとユーザーをまだ設定していない場合は、`server` と `user` も設定します。終わったら、もう一度起動してください。このファイルは起動時にしか読み込まれません。
5. **表示されたチームリンクを開きます**。リンクはチーム内だけで共有してください。リンクを知っていれば誰でもビルドを開始できます。

P4 でサーバーの信頼 (trust) やログインが必要な場合は、ビルドマシンのウィンドウに入力を求める表示が出ます。最初のビルドは 1 分以内に始まります。

## 使い方

- **一番上のパネル**に今の状況が出ます。ビルド中なのか、ビルドが通っているのか、壊れているのかが分かります。自動で更新されるので、ページは開いたままにしておきましょう。
- **ビルドは自動で始まります**。サブミットから 1 分以内です。
- **今すぐビルド**を押すと、最新のチェンジリストをすぐにビルドします。
- **リリースビルド**は、プレイヤーに配る版を一からビルドします。その分、時間がかかります。
- **ダウンロード**で、成功したビルドならどれでも取得できます。一番上のリンク (`/latest`) からは、いつでも最新のものが取れます。
- 右上の **English · 日本語 · 中文** でページの言語を切り替えられます。最初はブラウザの言語で表示されます。ビルドマシン自身のウィンドウ、設定ファイル、Discord への投稿は英語です。

ページにアクセスできる人なら誰でも、状況の確認とダウンロードができます。ビルドの開始には、チームリンクか、そこに含まれるトークンが必要です。

## ビルドをプレイする

チームには次の手順を送ってください:

1. ビルドマシンのページで「**ダウンロード**」をクリックします。
2. 展開します (Windows では右クリック ›「**すべて展開**」)。zip の中から直接ゲームを起動しないでください。
3. ゲームを起動します。Windows では `.exe`、Mac では `.app` です。
4. Windows に「Windows によって PC が保護されました」と表示されたら、「**詳細情報**」、「**実行**」の順にクリックします。macOS で開けない場合は、システム設定 › プライバシーとセキュリティで「**このまま開く**」をクリックします。ゲームに署名がないだけです。

## ビルドスクリプト

ビルドマシンは、`build.bat` (Windows) または `build.sh` (macOS、Linux) を、スクリプト自身のフォルダで実行します。そのとき、次の環境変数が設定されています:

| | |
|---|---|
| `BUILD_OUTPUT` | 空のフォルダ。ここに置いたものがダウンロード対象になります。 |
| `BUILD_KIND` | `test` または `release` |
| `BUILD_CHANGE` | ビルド対象のチェンジリスト |
| `BUILD_NUMBER` | ビルド番号 |

`build-machine.ini` に大文字の名前で書いた設定 (例: `GODOT = C:\Godot\godot.exe`) も、環境変数としてスクリプトに渡されます。

`0` で終了すると成功です。Godot と Unity のサンプルは、ゲームを数秒間実行し、クラッシュしたりエラーをログに出したりすれば失敗にします。どちらのエンジンも、起動した瞬間に壊れるゲームでもビルド成功と報告するからです。

ビルドの前に毎回、ワークスペースは P4 と同じ状態に戻されます。ただし、ディポの `.p4ignore` に書かれたものは残ります。エンジンのキャッシュフォルダ (`.godot/`、`Library/`、`Intermediate/`) を書いておけば、テストビルドは速いままです。リリースビルドではそれらも、P4 にないほかのものもすべて削除されます。ビルドマシンの `workspace` フォルダには、何も保存したりリンクしたりしないでください。

## 追加機能

以下では、`BUILD-PC` は P4 サーバーから見たビルドマシンのアドレス、`TOKEN` は起動時に表示されるトークンです。

### サブミットされた瞬間にビルドする

P4 のスーパーユーザーで、`p4 triggers` に次の行を追加します:

```
	buildmachine change-commit //MyGame/main/... "curl -s -m 5 -d reason=p4-trigger -d token=TOKEN http://BUILD-PC:8765/build"
```

サブミットした人には、`Change N submitted` のあとに `Build queued` と表示されます。ビルドマシンが止まっていると `'buildmachine' validation failed` と表示されますが、サブミット自体は通ります。

### P4 Code Review ですべてのレビューをテストする

1. `build-machine.ini` の `code_review_url` を設定します。例: `http://localhost:8080`
2. Code Review のプロジェクトに、ストリームを含むブランチ (例: `//MyGame/main/...`) があることを確認します。ないと、ストリームでシェルブしてもレビューになりません。
3. ワークフローにテストを追加します。URL は `http://BUILD-PC:8765/build`、ボディは URL エンコードで次のとおりです: `change={change}&status={status}&update={update}&token=TOKEN`

各レビューは最新のコードをマージした状態でビルドされ、成功か失敗かがログへのリンク付きで表示されます。ロックされた (`+l`) ファイルも、シェルブした人がチェックアウトしたままでアンシェルブできます (P4 2026.1 で確認)。サーバーに拒否される場合は、シェルブした人が、シェルブしたあとでそのファイルをリバートする (元に戻す) 必要があります。"There was no response" (応答がありませんでした) と出たら、Code Review から `BUILD-PC` に接続できていません。

### Windows と Mac の両方でビルドする

それぞれでビルドマシンを動かします。`stream` と `project_folder` は同じにして、`name` は `MyGame (Mac)` のように別々にしてください。ページ、zip、Discord の投稿で、どちらのものか分かるようになります。ワークスペース、ページ、トークンはそれぞれ別で、どちらもサブミットのたびに自分のスクリプトでビルドします。すぐにビルドさせたい場合は、`buildmachine-win` と `buildmachine-mac` のように名前を変えたトリガー行を、それぞれに用意してください。同じ名前の行が 2 つあると、P4 は最初の 1 つしか実行しません。Code Review では、それぞれにテストを追加します。

### コンテナで動かす P4

[p4-server-docker](https://github.com/jase-perf/p4-server-docker) などを使う場合:

- **Docker Desktop:** `BUILD-PC` には `host.docker.internal` を使います。
- **Windows の Podman:** コンテナからビルドマシンに接続できないので、トリガーと Code Review のテストは使わないでください。それでもビルドは自動で始まります。

Docker Desktop と Podman を同時に動かさないでください。

### Discord

`build-machine.ini` の `discord_webhook` を設定すると、成功や失敗のたびにチャンネルへ投稿されます。

![ビルドごとに 1 行ずつ投稿される Discord チャンネル。失敗には赤いバツ、成功には緑のチェックが付き、それぞれにチェンジリスト、サブミットしたユーザー、説明、ページへのリンクが載っている](images/Discord_Updates.png)

## 知っておくと便利なこと

- **P4 のログインには期限があります**。デフォルトは 12 時間です。ページに P4 のパスワードの問題が表示されたら、ビルドマシンを再起動して、そこでログインしてください。長いジャムでは、ビルドマシンのユーザーを、`Timeout` を長くした P4 グループに入れておきましょう。
- **Godot:** ビルド用のパソコンにエクスポートテンプレートをインストールし、`export_presets.cfg` と `.uid` ファイルをサブミットしてください。`godot` が PATH に (Mac ではアプリケーションフォルダに) ない場合は、`build-machine.ini` の `GODOT` に Godot の実行ファイルを指定します。Windows では `_console.exe` のほうです。
- **Unity:** プロジェクトと同じバージョンの Unity を Unity Hub で既定のフォルダにインストールし、サインインしてください (Personal で大丈夫です)。スクリプトはそこから Unity を見つけます。それ以外の場合は、`build-machine.ini` の `UNITY` を設定します。`BuildScript.cs` は `Assets/Editor` に置いたままにし、`.meta` ファイルもサブミットしてください。
- **Unreal:** Windows では、ランチャー版のエンジンと、登録済みのソースビルド版をスクリプトが見つけます。Mac ではランチャー版だけです。それ以外の場合は、`build-machine.ini` の `UE_ROOT` を設定します。C++ プロジェクトには Visual Studio (Windows) が、Mac でのビルドには Xcode が必要です。リリースビルドは Shipping でパッケージ化するので、中のゲームは `UnrealGame.exe` ではなく `UnrealGame-Win64-Shipping.exe` になります。

## 制限

パソコン 1 台、ストリーム 1 つ、ビルドは一度に 1 つです。直近 20 件のビルド (`keep_builds`) と、種類ごとの最新の成功ビルドを残します。OS のサービスとして常駐するわけではないので、パソコンを再起動したら、ビルドマシンをもう一度起動してください。

これで足りなくなったら、P4 を使うチームの次の定番は、TeamCity (無料版にビルドエージェントが 3 つ付きます)、P4 プラグインを入れた Jenkins、Unreal なら Horde です。ビルドスクリプトはそのまま使えます。

## セキュリティ

- ページにアクセスできる人なら誰でも、ビルドを見てダウンロードできます。共有 Wi-Fi では、ほかのチームも含まれます。
- ビルドの開始にはトークンが必要です。トークンもページと同じく、暗号化されていない HTTP で送られます。
- ブラウザは、チームリンクの Cookie を、ポートに関係なくビルド用パソコン上のすべての Web サーバーに送ります。そのため、同じパソコンのほかのサーバーもトークンを読めます。
- トークンが漏れたら、`token.txt` を削除して再起動し、トリガーと Code Review のテストを更新してください。
- サブミットできる人は誰でもビルドスクリプトを変更でき、ビルドマシンはそれを実行します。

## 動作確認環境

Windows 11、Python 3.13、Godot 4.7.2、Unity 6000.3、Unreal 5.7、P4 2025.x と 2026.1、P4 Code Review 2026.3。Godot と Unity は、ビルドマシンを通して最初から最後まで動かしました。Unity と Unreal のリリースビルドは手動で実行しました。Godot の `build.sh` は Ubuntu で実行し、Linux 用ビルドマシンのビルドと起動も Ubuntu で行いました。未テスト: macOS 関連すべて (`build.sh` スクリプトの Mac 部分と、Mac 用ビルドマシン)、Unity と Unreal の `build.sh` スクリプト、Discord。
